# 公差分析工作台（联合装配合格率 + 加工参数优化）

从一份**成组测量**出发，估计装配体的**联合合格率**（所有装配约束同时满足的概率），
并在加工调整预算内寻找最有效的**中心值偏移 / 标准差收紧**。

> 多个尺寸各自合格，并不说明成品装配一定合格。本工具把每一次模拟当作一个真实零件
> （一行测量 = 一个零件），按零件保留相关结构，再逐个判断全部装配约束。

零依赖：Node 标准库 + 原生 JS/SVG，无构建步骤，无网络请求。

---

## 快速开始

```bash
npm install        # 仅测试需要（jsdom）
npm start          # http://localhost:4173
npm test           # 28 个单元 / API / 端到端 UI 测试
```

页面顶部的五个标签就是完整流程：

| 标签 | 做什么 |
|---|---|
| ① 输入 | 载入示例、粘贴方案 JSON/CSV、**从空项目搭建**（零件 → 测量表 → 约束 → 成本 → 预算） |
| ② 联合模拟 | 联合合格率 vs 单尺寸合格率、逐约束失败构成、分布直方图、尾部敏感性、抽样稳定性、逐次模拟明细下载 |
| ③ 解释与验证 | 二维截面（可锁定第三个工艺参数）、零件内相关矩阵、单尺寸 vs 联合、穷举 / 数值积分 / 跨种子对照 |
| ④ 调整优化 | 推荐参数版本、收益–成本帕累托前沿、单项调整排序、替代候选、被拒候选及原因、外推检查 |
| ⑤ 方案对比 | 同一批随机数下的原方案 vs 候选方案配对差、逐约束变化、成本与可行性、方案与明细导出 |

## 模型与不变量

### 1. 一行 = 一个零件

每个零件一张测量表：行是真实零件，列是该零件的尺寸。**行从不拆散、从不逐列重排**：

- 经验重采样按**行**有放回抽取（`src/core/sampling.js`），同一零件的尺寸天然成组出现，相关结构原样保留。
- 参数分布按零件拟合相关矩阵，用 Cholesky 一次抽一个联合向量；相关矩阵先做收缩（`correlationShrinkage`），
  非正定时退化为特征值截断，并在结果里给出警告。

页面同时给出一个**明确标注为错误对照**的独立重排（`invalid: true`）：把每列分别打乱后再算一次。
它破坏零件内相关，通常会**高估**联合合格率——这正好说明为什么不能把各维随机重排当作联合样本。
强相关反例（`pump-body-correlation`）里，真实合格率约 50%，独立重排对照约 62%。

### 2. 联合合格率是 AND，不是乘积

每次模拟对**全部**约束求值，只有全部通过才算这一次装配合格：
`joint = mean(AND_k pass_k)`。单尺寸合格率之积只作为对照量展示；
相关为正时乘积高于联合（尺寸共同摆动，缺陷集中出现），相关为负时可能相反。
任何一条约束没有通过，这次模拟就算失败，并记录具体原因。

### 3. 调整只改加工参数，不删样本

一个**参数版本**是：

```json
{ "shifts": { "body.centerDist": 0.0025 }, "sigmas": { "housing.depth": 0.9 } }
```

有效参数 = 方案基准参数 + 调整（中心值偏移、标准差倍率）。
`materializeVersion()`（`src/core/params.js`）是**唯一**的参数来源：模拟、成本、可行性、外推判断
全部读同一份物化结果，并输出版本指纹（fingerprint）。每次响应都会回传该指纹，
优化结果还会做服务端一致性校验（`fingerprintMatches`、`costMatches`）。
成本按 `perShift·|Δshift| + perSigma·σ收紧量` 计算，预算是硬上限；
可行性另受 `maxShift`、`minSigmaScale`、禁止放大 σ、锁定变量约束。

### 4. 外推显式标注

- 变量声明 `assumed`（无测量数据，如新供应商尺寸）→ 直接标记 `extrapolated`，含它的约束在解释里标注“外推”。
- 参数分布下，若某条约束的 1%/99% 分位落在观测范围之外超过阈值 → 尾部覆盖度为 `partial`。
- 经验重采样不会越过观测极值，这本身就是它的边界；小样本尾部的差异在“尾部敏感性”里并排给出五种口径。

### 5. 对照与验证

`/api/verify`（标签③）同时给出：

- **精确穷举**：约束涉及的零件行数乘积 ≤ 150 万时，枚举所有测量行组合，得到经验模型的精确解（无 MC 误差）。
- **确定性数值积分**：约束只涉及 ≤ 2 个正态族尺寸时，在 321×321 网格上积分（含相关系数），作为解析对照。
  超过 2 维或非正态族会明确返回“不适用”，而不是假装有结论。
- **跨种子稳定性** 与 **样本量收敛曲线**；页面另有批均值稳定性条。

判定阈值与抽样误差挂钩（`4·SE + 小量`），一致 / 不一致都会写明。

## 优化搜索

`src/core/optimize.js`，确定性、种子固定、按评估次数封顶：

1. **OAT 探针**：逐个变量尝试中心值网格（含由约束推出的中点）与 σ 收紧步长；
2. **贪心打包**：每次加入在当前预算下增益最大的可行步，直到无增益或预算用尽；
3. **坐标细化**：对打包结果逐个变量微调。

输出推荐版本、帕累托前沿（收益 vs 成本）、单项调整排序、替代候选、
被拒候选及其违反项（预算 / 工艺限值 / 锁定 / 无增益）。所有候选都已按同一版本模拟与计价。

### 对比是配对的

`/api/compare` 用**共同随机数**：先按一个种子构建一份样本集，再分别代入两个参数版本。
同一次抽样在两个版本下的通过指示量逐次配对，差值是配对差均值，并给出正态置信区间与
`bothPass / onlyBase / onlyCand / neither` 四格计数。这样比较的是版本，而不是抽样噪声。

## API

所有 POST 接口都接受 `{ scenario, options: { method, draws, seed, tailMode }, version }` 之类字段；
未提供的走方案默认值。错误统一为 `{ error }`，参数校验失败为 HTTP 400。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/scenarios` | 示例方案列表 |
| GET | `/api/scenarios/:file` | 单个示例方案 JSON |
| POST | `/api/analyze` | 基础分析：联合/单尺寸合格率、逐约束、尾部敏感性、零件统计 |
| POST | `/api/simulate` | 在给定参数版本下重跑模拟 |
| POST | `/api/distributions` | 单条约束的分布序列（经验/正态/t copula/错误独立对照） |
| POST | `/api/section` | 二维截面点集（可 `fixKey`/`fixValue` 锁定第三个参数） |
| POST | `/api/verify` | 穷举 / 二维积分 / 跨种子 / 收敛对照 |
| POST | `/api/optimize` | 参数版本优化（预算、锁定、评估上限） |
| POST | `/api/compare` | 共同随机数下的配对对比（原 vs 候选） |
| POST | `/api/export/failures` | 逐次模拟 CSV：`joint_pass`、逐约束 `_value/_pass/_reason`、尺寸值 |
| POST | `/api/report` | 一次性汇总报告 JSON |

场景格式（简化）：

```jsonc
{
  "name": "…",
  "budget": { "total": 50, "currency": "元" },
  "simulation": { "seed": 20261124, "drawsPerPart": 4000, "method": "empirical", "tailSensitivity": true },
  "parts": [{
    "id": "body", "label": "泵体",
    "variables": [{
      "id": "boreA", "label": "孔径", "unit": "mm", "dist": "auto", // auto|normal|t|lognormal
      "spec": { "lower": 11.95, "upper": 12.05 },
      "cost": { "perShift": 900, "perSigma": 700, "maxShift": 0.012, "minSigmaScale": 0.55 },
      "locked": false,
      // 或无测量时： "assumed": { "mean": 12, "sd": 0.01, "dist": "normal" }
    }]
  }],
  "datasets": { "body": { "columns": ["boreA", "boreB"], "rows": [[11.99, 12.01], …] } }, // ≥3 行
  "constraints": [{
    "id": "overPins", "label": "跨棒距",
    "terms": [ { "part": "body", "variable": "centerDist", "coef": 1 }, … ],
    "lower": 29.994, "upper": 30.006
  }]
}
```

## 限制（明确写在页面上，也在这里）

- **数值积分只覆盖 ≤ 2 维、正态族**；更多维度或重尾分布请看穷举（若可行）与跨种子稳定性，而不是一个假的解析值。
- **经验重采样被观测极值截断**：它不会产生比测到的更坏的零件，因此对尾部风险的估计偏乐观。小样本请对照参数分布口径。
- **参数分布是拟合假设**：t copula 的尾相关强度取决于自由度设置（默认 ν=5），页面提供敏感性对照而非单一真值。
- **成本模型是线性的**（每单位偏移 + 每点 σ 收紧），不含换刀、停机、夹具改造等固定投入；预算可调但成本函数需按工艺实际替换。
- **装配约束是线性叠加**：几何非线性（角度、间隙铰链）需先在测量表里折算成线性贡献项。
- 示例数据全部虚构，仅用于演示方法与反例，不代表任何真实零件。

## 测试覆盖

`npm test` 运行 28 项：

- 方案校验（未知引用、行数下限、无测量零件、上下界）；
- 行保留与相关保留（经验 / 参数 / 独立重排的对照）；
- `applyVersion` 仿射性（偏移只移均值、σ 只缩放离散度）；
- 同一版本的模拟/成本/可行性一致性、硬预算与工艺上限、锁定；
- 联合 = AND、强相关陷阱、外推标注、尾部部分覆盖；
- 穷举 vs MC、二维积分 vs MC；
- 优化器在所有示例上预算内、可行、确有增益，且指纹与成本自洽；
- API 全链路（analyze → optimize → compare → CSV 导出 → 400 校验）；
- jsdom 驱动真实页面：示例流程、**从空项目搭建**流程（含二维截面、参数锁定、验证、优化、对比），以及**拖放导入**（方案 JSON 与测量表 CSV）。

无浏览器环境，UI 测试用 jsdom 加载真实页面脚本并对真实服务器发请求；它验证接线与数据，不验证像素布局。
